# concertify

Small app that uses Setlist.fm + Spotify to build playlists from artist setlists and user's top tracks.

This repository contains:
- `server/` - Express backend that handles Spotify auth, talks to Setlist.fm, caches in Redis, and generates playlists.
- `frontend/` - Next.js frontend (dev on port 3000).
- `docker-compose.yml` - bring up Redis, server and frontend for local development.

## Requirements
- Node.js 18+ (for local runs)
- Docker & docker-compose (optional)
- Redis (docker-compose includes it)
- Spotify Developer account (client id & secret)
- Setlist.fm API key

## Environment variables
Create a `.env` file in the project root (or pass env vars into docker-compose). The server expects:

- `SPOTIFY_CLIENT_ID` - Spotify app client id
- `SPOTIFY_CLIENT_SECRET` - Spotify app client secret
- `SPOTIFY_REDIRECT_URI` - Redirect URI for Spotify OAuth (default: `http://localhost:3000/callback`)
- `SETLISTFM_API_KEY` - Setlist.fm API key
- `REDIS_URL` - Optional Redis connection (default: `redis://localhost:6379`)
- `PORT` - Optional server port (default: `4000`)

Example `.env`:

```
SPOTIFY_CLIENT_ID=your_client_id
SPOTIFY_CLIENT_SECRET=your_client_secret
SPOTIFY_REDIRECT_URI=http://localhost:3000/callback
SETLISTFM_API_KEY=your_setlist_key
REDIS_URL=redis://localhost:6379
PORT=4000
```

## Run locally (recommended for development)

1. Install dependencies for both server and frontend:

```bash
cd server
npm install
cd ../frontend
npm install
```

2. Start Redis locally (or use docker):

```bash
docker run -p 6379:6379 --name concertify-redis -d redis:7
```

3. Start the server:

```bash
cd server
export $(cat ../.env | xargs) # or set env vars manually
npm run dev
```

4. Start the frontend:

```bash
cd frontend
npm run dev
```

Open the frontend at http://localhost:3000

## Run with docker-compose (one command)

This repository includes a `docker-compose.yml` which will start Redis, the server and the frontend. It mounts the local folders so changes are seen by containers.

Set environment variables in your shell or in a `.env` file and then:

```bash
docker compose up --build
```

Frontend will be on http://localhost:3000 and the server on http://localhost:4000

## How it works (high level)

- Frontend requests a Spotify auth URL from the server (`/auth/url`) and performs OAuth with Spotify. The server exchanges the code for tokens at `/auth/callback`.
- The frontend sends the user's access token in Authorization headers (Bearer) to endpoints like `/api/top-tracks` and `/api/generate`.
- The server queries Setlist.fm (using `SETLISTFM_API_KEY`) to fetch setlists and maps setlist song titles to Spotify tracks via the Spotify Search API.
- Playlists are generated by scoring candidate tracks using audio-features similarity to the user's top tracks.

## API endpoints (quick)

- GET `/auth/url` -> { url } (spotify auth url)
- GET `/auth/callback?code=...` -> exchanges code for tokens
- GET `/api/top-tracks` (Authorization: Bearer <token>) -> cached Spotify top tracks
- GET `/api/setlists/artist/:mbid` -> setlists for an artist by MusicBrainz id
- POST `/api/generate` (Authorization: Bearer <token>) -> body: { seeds: { artistId, setlistMbId, artistName } }

Example curl to generate playlist (replace <TOKEN> and seeds):

```bash
curl -X POST http://localhost:4000/api/generate \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"seeds":{"artistId":"1vANZV20H5BQyI4V1s1Kpb","setlistMbId":"6bd7f1f8","artistName":"Radiohead"}}'
```

## Troubleshooting
- If you get 401 from Spotify endpoints, check the access token and that it hasn't expired. The server currently returns tokens from `/auth/callback` but does not persist refresh tokens — in production you should store refresh tokens server-side.
- If Setlist.fm returns errors, ensure `SETLISTFM_API_KEY` is valid and your app respects rate limits.
- If Redis isn't reachable, set `REDIS_URL` to a running Redis instance or start Redis via Docker.
